# sealr 0.1.0-alpha.17

Alpha.17 establishes the current owner-controlled Sealr source and native
distribution for Nick Seal (`blisspixel`). It preserves the verified archive
boundary, twelve explicit format selections, typed publisher outcomes, tested
consumer migrations, and named existing durability controls. This release
changes distribution and history management, not runtime archive semantics.

The Alpha.1 through Alpha.16 remote releases and tags are retired. Their
versioned notes, measurements, and source digests remain historical records,
not current acquisition instructions. Old immutable tag names are not reused.
See [distribution history](../distribution-history.md).

## Verified archive boundary

Consumers obtain bounded member-read authority from `VerifiedArchive` and check
requested effects independently. Inspection cannot satisfy a requested write,
and failed publication can preserve verified content without claiming committed
output. Typed publisher failures retain their explicit stages and codes;
successful reports and CLI exit classes stay compatible.

The evidence migration refuses legacy and mixed canonical lineages without
fallback and leaves verified rejection evidence consumer-denied. Named
`Durability::FlushOnly` and `Durability::MemberSync` preserve historical policy
bytes, digests, and worker encoding. Neither mode adds directory syncing,
crash recovery, or power-loss durability. No parser, codec, runtime dependency,
worker protocol, profile identity, or policy identity is changed here.

## Owner-controlled release and fresh assurance history

The authenticated owner creates the exact empty prerelease draft. GitHub Actions
builds, tests, attests, and stages its artifacts without creating a release
under another author. The trusted publisher verifies the owner, protected-main
commit, exact CI and fuzz runs, notes, checksums, provenance, and immutable
release readback before completing publication.

All active assurance qualification histories restart at zero. Retired workflow
runs and repository identities cannot qualify the new history. The historical
September 13 observation remains unchanged, the ten-distinct-commit rule still
applies, and no category is eligible or promoted. Mutation and coverage remain
discovery-only.

Compiler-accurate API comparison now uses the new source-only tag
`source-baseline-20260913`, pinned to commit
`157d47168ea7bdab1a5d0a1a7c2c8ec896d195d1`. Its baseline source package retains
the Alpha.16 version; no retired release tag or native artifact is required.

This is a GitHub-only development preview, not a crates.io publication, stable
API freeze, independent security audit, or production-containment claim. The
[release page](https://github.com/blisspixel/sealr/releases/tag/v0.1.0-alpha.17)
records publication state. Authenticate the new artifacts using
[release verification](../release-verification.md); do not substitute an old
native companion or infer availability from an archived report.

The [roadmap](../../ROADMAP.md) still prioritizes measuring time spent in
source hashing, plan validation, worker setup, and payload work before a runtime
performance change, followed by lifecycle and coordinated dependency work.
Historical Alpha.15 read measurements retain their original provenance and
are not an Alpha.17 performance claim.
