# sealr 0.1.0-alpha.9

This ninth development preview adds an explicitly selected, zero-new-dependency portable POSIX ustar path and the format-selection core needed to extend Sealr beyond ZIP without changing the compatibility default. It preserves every published ZIP profile, identity vector, wheel result, and the Alpha.6 reduced-authority Linux boundary.

It remains a preview. The default APIs still run in process, structural planning is not confined, successful supervised execution remains ZIP-only on x86_64 Linux with Landlock ABI 3, and this release does not claim general TAR compatibility, process containment, or production readiness.

## Portable POSIX ustar

- `sealr.profile.tar.ustar-portable.v1` accepts exact raw POSIX ustar regular files and directories through explicit `ArchiveSelection::TarUstar` and policy v2 authorization.
- The parser validates exact `ustar\0` and `00` markers, fixed-width ASCII text, a closed ASCII-octal numeric grammar, header checksums, canonical member geometry, zero padding, two zero-block termination, and zero trailing record padding.
- PAX and GNU extensions, base-256 numbers, links, sparse records, device nodes, FIFOs, concatenated archives, recovery behavior, and compressed wrappers are closed as unsupported or denied according to the published profile. Filenames never select the parser.
- TAR uses format-native public evidence and `sealrTreeV2` layout identity. ZIP keeps its existing serialization and `sealrTreeV1` identities byte-for-byte.
- Public member evidence is format-native. ZIP method, flags, CRC, compressed size, source ranges, extra fields, and creator metadata are available only through `zip_evidence()`; TAR evidence is available through `tar_evidence()` and never exposes ZIP facts.
- The canonical profile digest is `3c87c5ec4c1ad5377eb60ebb308e9e394aaf7a4133dddf5587829b4510af1700`.

## Policy, API, and effects

- `sealr.policy.v2` authorizes exact canonical subsets of ZIP and portable ustar profiles. The Alpha.8 ZIP-only v1 policy and digest remain unchanged.
- Policy v1 retains its exact canonical bytes, digest, authorization behavior, and ZIP compatibility facade.
- `apply_with_options` and the CLI accept an explicit archive selection. `apply()` remains the strict ZIP compatibility facade.
- TAR members reuse the bounded snapshot, quota, verified-read, retention, and atomic materialization core. A downstream extracted-crate consumer retains one member and reads another after the original TAR bytes have gone out of scope.
- Selecting TAR with the authenticated Linux worker fails closed as typed isolation unavailable. There is no in-process fallback and no destination or staging side effect.

## Independent evidence

- A standalone verifier validates the declared TAR covering geometry and evidence digests, then reconstructs the portable ustar profile, TAR layout, and content roots without depending on the Sealr crate. Exact sparse producer fixtures separately reconstruct, hash, and apply source bytes.
- Exact sparse fixtures from GNU tar 1.35, bsdtar 3.8.4, and Python 3.12.10 prove producer interoperability within the narrow profile.
- Field-family mutations cover checksum, dialect, numeric, owner, padding, terminator, type, and unsupported-feature boundaries.
- Typeflag classification is exact: NUL and `0` are regular files, `5` is a directory, named extension values are unsupported, and unknown values are malformed. Malformed structure is reported before quota findings, and zero validation scans every member-padding and trailing-record-padding byte without allocating the range.
- A dedicated bounded libFuzzer target starts from 15 manifest-pinned states, including valid empty, multi-member, and GNU tar archives, then combines untouched bytes with checksum-repaired header mutations, quota-frontier replay, deterministic repeat parsing, and source-geometry assertions. Release promotion requires exact-commit success for protocol, semantic-record, and raw-ustar campaigns.
- Native package verification exercises TAR inspect and materialization on Linux, macOS, and Windows, plus the Linux worker no-fallback refusal.
- The covering oracle now converts scratch-allocation failure into a deterministic error finding instead of panicking.

## Multi-format direction and dependency budget

- The format matrix now separates containers, compression wrappers, advanced features, consumer profiles, stateful layer semantics, supervised availability, and dependency cost.
- Format-native evidence, one explicit retained payload plan per member, a non-cloneable format-neutral `ReadyArchive` execution authority, and domain-zero raw snapshots with an empty transform graph are implemented. The remaining gate before gzip/TAR is a bounded private derived-snapshot constructor with transformation identity binding.
- Planned sequencing is ZIP64, gzip/TAR, PAX and GNU TAR, zstd/xz/bzip2 wrappers, cpio and ar/deb, 7z, CAB, RPM, consumer profiles, OCI layer semantics, and separately researched RAR4 and RAR5 support.
- Raw ustar adds no direct or transitive runtime dependency and leaves the dependency graph unchanged.

## Distribution and verification

- Only the `sealr` library crate is allowlisted for crates.io publication. Required CI verifies its exact 58-file package, package-root README and Apache-2.0 license, Rust 1.98 metadata, and separately locked extracted-package consumer.
- The tag workflow produces exactly the Linux x86_64, macOS arm64, and Windows x64 native archives plus `SHA256SUMS` and GitHub build-provenance attestations. It does not publish the crate to crates.io.
- Promotion requires exact-main Required CI, exact-commit three-target fuzz evidence, target-specific third-party license closure, release-candidate classification, draft-asset readback, and immutable-release verification.

## Important limitations

- `apply()` continues to select ZIP strict ASCII v1 for compatibility. Portable ustar is explicit and requires policy v2.
- Only raw portable ustar regular files and directories are implemented. PAX, GNU extensions, sparse files, links, special files, compressed TAR, ZIP64, 7z, RAR4, RAR5, cpio, ar, deb, RPM, CAB, APK signing semantics, and OCI layer semantics remain future work.
- The authenticated Linux worker remains ZIP-only. TAR is supported in process and fails closed when a worker is requested.
- Stable API and identity review, accumulated assurance history, authenticated recovery, complete durability, an external adopter, and independent security review remain roadmap gates.
