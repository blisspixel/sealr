# sealr 0.1.0-alpha.14

Alpha.14 fixes incomplete Deflate stream admission and adds reproducible Unicode
and streaming wheel evidence. It retains the twelve explicit container and
codec selections, public wheel evaluator, authenticated Linux worker, canonical
evidence verifier, copied PyPA handoff, and exact Poetry 2.4.2 fixture.

This is a development preview for evaluation and integration work. It is not
production containment, malware detection, independent security review, or a
stable API and evidence freeze. This GitHub-only prerelease does not publish a
crate to crates.io.

## Deflate completion correction

A controlled CPython wheel with its Deflate BFINAL bit cleared previously passed
admission. Its complete plaintext, CRC32, expanded size, and compressed-input
consumption were unchanged, but an independent zlib decoder reported that the
stream never completed.

The shared bounded reader now requires explicit `StreamEnd` before successful
EOF. Complete input consumption, output accounting, and integrity checks remain
separate requirements. The correction covers ZIP32, ZIP64, supervised payload
verification, later capability reads, and gzip framing. Existing syntax-error
diagnostic identities are preserved. The malformed stream now fails closed as
`codec.deflate.invalid_stream`.

No profile, policy, tree encoding, consumer digest, runtime dependency, or
`unsafe` code was added. This corrects enforcement of the existing complete-stream
language. Evaluators should use Alpha.14 or later; Alpha.13 artifacts remain
historical reproduction evidence and must not be retroactively published to
crates.io.

## Targeted compatibility evidence

The [24-artifact producer matrix](../wheel-producer-compatibility.md) pins complete
source bytes and SHA-256 values from CPython 3.12.10 with zlib 1.3.1, exact
derivations, member contents, outcome sequences, install plans, and identities.

- Six admitted fixtures cover Store and Deflate with seekable output, signed
  streaming descriptors, and explicit unsigned-descriptor derivatives.
- Each admitted fixture contains fourteen members and eight Unicode paths,
  covering Latin, Greek, CJK, and all five wheel install schemes.
- Sixteen archive refusals cover descriptor disagreement, encoding flags,
  payload integrity, incomplete Deflate, normalization, case-fold collisions,
  and traversal.
- Two archive-valid wheels fail semantic evaluation on their incorrect RECORD
  hashes, preserving the distinction between container and consumer denial.

The packaged cross-platform regression removes source files before evaluation,
checks every bounded member read, and compares native materialization with
inspect against committed observations. Required Linux CI completes twelve
supervised installations through the copied public-API handoff and checks all
eighteen negative cases. The admitted runs independently verify canonical
evidence, remove the source before Python, forbid post-boundary wheel opens,
audit exact installed paths and executable modes, and require inspect and
materialize realization parity.

These fixtures do not increase the 300-artifact published-wheel inventory or
claim external adoption. Real adopter artifacts and separately maintained
consumer feedback remain the next product gate.

## Adoption and candidate stability

The release includes the machine-checked adopter contract and classified
candidate surface inventory introduced after Alpha.13. The adopter contract
separates immutable historical Alpha.13 artifact identities from the current
Alpha.14 evaluation source and copied-handoff version requirement. Historical
hashes are not reassigned to a newer release. The inventory remains unfrozen.

The roadmap prioritizes a separately maintained consumer, measured compatibility
and API friction, lifecycle closure, and independent review. Parser breadth
remains frozen. GitHub-only source acquisition for evaluation is not an ordinary
registry pilot, and copied examples do not satisfy external usefulness.

## Validation and distribution

Required CI covers full workspace tests and native materialization on Linux,
macOS, and Windows, strict Clippy, Rust formatting and documentation, exact
crate and native packages, the 5,927-case ZipDiff gate, dependency and license
contracts, the independent verifier, both installer fixtures, and the real
kernel floor. Release promotion additionally requires the fourteen exact-commit
bounded fuzz campaigns, all three native release builds, checksums, provenance,
and immutable-release verification. Those are bounded evidence categories,
not an exhaustive proof or an external audit.

Rust 1.98 remains the MSRV. Native floors remain Ubuntu 24.04 x86_64 with glibc
2.39 and Linux 6.8, macOS 15 arm64, and Windows Server 2022 build 20348 x64.
Supervised mode additionally requires the supported x86_64 Linux Landlock ABI 3
and seccomp setup. ZIP64, TAR, and 7z worker selections remain unsupported and
fail closed without fallback.

Download the native archive for the appropriate target and `SHA256SUMS` from
the [immutable release](https://github.com/blisspixel/sealr/releases/tag/v0.1.0-alpha.14).
Follow the [verification guide](../release-verification.md) before extraction
or execution. Every archive contains the CLI, independent evidence verifier,
README, changelog, project license, and target-specific third-party notices;
the Linux archive also contains the authenticated worker and manifest.

Receipts remain unsigned. Durable directory publication, authenticated abandoned
stage recovery, same-user hostile-process containment, external adoption, and
independent security review are not complete. The [README](../../README.md),
[security policy](../../SECURITY.md), and [API contract](../api.md) state the
supported boundary and remaining limitations.
