# sealr 0.1.0-alpha.19

Alpha.19 explains a refusal in the terminal and pins finding-code discriminants.
Admission, policy bytes, and the view and receipt schemas are unchanged, except
for one terminal case: when stderr is a terminal and neither `--json` nor
`--receipt` is set, the summary is printed on stderr even if stdout is piped.
The view JSON still goes to stdout in that case.

## Terminal result

Exit 0 says `allowed`. Exit 2 says `rejected`. Exit 3 says `not written`.
When the destination already exists, the summary gives the next step and does
not replace the library detail. A refusal names the member when the header has
one. A 7-digit ustar checksum notes the git archive and npm shape and stays a
refusal. An xz stream selected as gzip names `tar-xz-ustar`. A symlink typeflag
says symlink. A PAX keyword outside the closed profile names that keyword. A
PAX header under a ustar selection names the sibling `--format`.

`--color auto` follows the terminal and the usual `NO_COLOR`, `CLICOLOR`,
`CLICOLOR_FORCE`, and `TERM=dumb` rules. `NO_COLOR` wins over `CLICOLOR_FORCE`.
`--color always` ignores the environment. Color uses only the named green, red,
and yellow verdicts, a bold finding code, and a dim detail. JSON is never
colored. After a written admitted tree, a terminal adds one dim content-tree
preview from the first 16 hex characters of the unsigned `sealrTreeV1` identity.

`--machine` writes one `sealr.command-result.v1` document on stdout. It is not
`--json`. Combining it with `--json` or `--canonical` exits 2. Clap syntax
errors do not emit the envelope. If a view or receipt file cannot be written
after a committed destination, the process exits 1, `semantic_exit` preserves
the admission result, and the destination is not rolled back.

## Finding codes

Numeric discriminants of existing variants match source-baseline-20260913.
`ZipSymlink` is 79. Strings from `as_str()` remain the wire format. New
variants append. Semantic-record tags were not renumbered.

## Toolchain

Rust 1.99.1 is the pinned compiler and Rust 1.99 is the declared MSRV. The
workspace uses edition 2024. Fuzzing pins `nightly-2026-10-31`. Required
Windows jobs use `windows-2025`, Windows Server 2025, NT build 26100. The
Poetry fixture stays on CPython 3.12 because its wheelhouse is cp312. Kani
0.67.0 stays on Rust 1.93. Required CI still compiles the product with the
workspace toolchain. Wrapped help pulls `terminal_size` 0.4.4 into the native
license bundles. The `sealr` crate runtime graph is unchanged.

Alpha.17 remains the published native distribution until Alpha.19 artifacts
exist. Authenticate the published archives with
[release verification](../release-verification.md). Do not substitute an older
companion for a future archive or infer checksums that have not been published.

This is a GitHub-only development preview, not a crates.io publication, stable
API freeze, independent security audit, or production-containment claim.

The [roadmap](../../ROADMAP.md) still prioritizes measuring time spent in
source hashing, plan validation, worker setup, and payload work before a runtime
performance change, followed by lifecycle and coordinated dependency work.
Historical Alpha.15 read measurements retain their original provenance and
are not an Alpha.19 performance claim.
