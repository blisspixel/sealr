# Changelog

All notable changes to sealr are documented in this file.

The project is in initial development. Compatibility may change between preview releases, and every such change must be documented here.

## [Unreleased]

### Added

- Added full-integrity supervised prefix reads to the authenticated Linux `VerifiedArchive` backend. A distinct private request kind binds the prefix cap to the exact source, accepted plan, completion, member, and originating effect while preserving existing full-read record bytes. The worker streams the complete Store or Deflate member; the supervisor retains at most the requested prefix and independently checks complete size, CRC32, SHA-256, exact EOF, correlated success, clean exit, and reap before releasing any bytes. Helper feature generation 2 prevents an older helper from accepting the new request shape before source transfer. Deterministic evidence covers zero, short, exact, oversized, and effectively unbounded caps, cross-kind rejection, wrong size, CRC32, SHA-256, and retained length, discarded-tail corruption, cancellation, timeout, post-result crash recovery, clones, repeated reads, and descriptor and child cleanup. The extracted-package consumer now evaluates a supervised `.data/scripts` wheel through this prefix path with no fallback.

## [0.1.0-alpha.12] - 2026-08-30

### Added

- Added the independent `sealr-identity-verifier` to every native release archive beside the `sealr` CLI. The shipped verifier now has explicit help, version, and exit-code contracts plus single-handle reads capped at the 16 MiB evidence limit plus one detection byte if an input grows after metadata inspection. Required Linux, macOS, and Windows package checks use only the extracted executables to produce admitted and rejected canonical evidence, verify it against the observed source, and refuse view, receipt, source, and pair-substitution tampering. The verifier remains separate from the Sealr crate and adds no dependency family to the native license closure. Users must authenticate the enclosing archive with `SHA256SUMS` and GitHub build provenance first; the verifier checks unsigned Sealr evidence and does not authenticate itself, a signer, or the live layout root.
- Added scheduled compiler-accurate public API compatibility discovery using `cargo-semver-checks` 0.49.0 on Rust 1.98. The workflow authenticates the exact x86_64 Linux release archive by SHA-256, proves `v0.1.0-alpha.11` still resolves to commit `a1f2bf62a5a432a20b045db327ce9a6e4bdf8f6b`, builds a self-contained Cargo package from that commit to avoid repository-only manifest ambiguity, forces a minor-release comparison so unchanged prerelease version text cannot skip checks, and retains the full log for 30 days. The first strict run found and fixed shifted implicit discriminants by restoring every published enum variant's Alpha.11 position. Three deliberate pre-freeze lint classes covering seven exact `Policy` and `RealizationIdentityError` shape changes remain pinned warnings; any warning-set drift or other deny-level break fails the job. This category remains non-promotable until a later release baseline removes that debt, after which its ten-run promotion history starts from zero.
- Added an isolated [packaged PyPA adopter conformance kit](tests/pypa-installer-consumer/README.md) against exact `installer` 1.0.1. It builds only against Cargo's extracted `sealr` package, independently verifies canonical view v2 and receipt v3 evidence, deletes the source before Python starts, stages bounded member bytes only through `VerifiedArchive`, enforces a `.whl` open audit hook, installs into five separate real roots, independently enumerates every output, and pins the source, tree, artifact, plan, and realization identities for both a controlled fixture and the real hash-pinned installer wheel. Required CI also proves denial before effects for a lying `RECORD`, traversal, descriptor tampering, and staged-member tampering. The first target is Linux POSIX with no bytecode and no overwrite. This is an adopter-ready repository contract, not independent external adoption.
- Added independent live canonical-evidence verification to `sealr-identity-verifier`. The no-Sealr-dependency tool verifies exact RFC 8785 view v2 and receipt v3 bytes, their pair and source bindings, registered interpretation and default-policy identities, outcome consistency, and the format-neutral content root across five committed cases, including source, view, and receipt tamper refusals.
- Added the runnable `same_digest_different_tree` demonstration and [its write-up](docs/same-digest-different-tree.md): one archive admitted and its file deleted, then evaluated under three outer filenames through the retained capability. Two benign spellings yield a byte-identical source digest, archive-tree identity, and installed target set but distinct filename-bound artifact and install-plan identities; a third, disagreeing name is denied with a typed finding. It turns the ZipDiff/uv archive-confusion lesson into a capability-path artifact — same digest is not same tree — rather than a citation.
- Added the [public API surface contract](docs/api-surface.md) with its compile-time machine half: `crates/sealr/tests/api_surface.rs` imports every supported public item by exact path and pins the core operation signatures through function-pointer coercions, so removing, renaming, or changing a pinned signature fails compilation, while pre-freeze additions remain permitted and land in both halves together. - Added the canonical RFC 8785 evidence lineage: `Outcome::canonical_evidence()` emits `sealr.view.v2` and `sealr.receipt.v3` documents whose bytes ARE the digested bytes — hashing the view bytes reproduces the receipt's `view_digest`, and hashing the receipt bytes produces its externally nameable digest. The documents carry identical semantic content to the shipped lineage (pinned by test), differing only in the schema identifiers, the receipt's `canonicalization` and `view_schema` binding fields, and the digest coverage; shipped `sealr.view.v1`/`sealr.receipt.v2` bytes are untouched, with the two new receipt fields provably absent from v2. A field-domain audit proved canonicalization total over every reachable evidence document — the only numeric fields are verified byte counts bounded by real ingested bytes — and the registered `evidence.canonicalization` finding fails closed with no bytes on any future regression. The CLI exposes the lineage through `--canonical`, valid only together with both `--view` and `--receipt` file flags: the files receive the exact canonical bytes with no trailing newline, presentation streams stay silent, semantic exit codes are unchanged, and a canonicalization failure discards both files and exits `1`.
- Added the CLI `--policy <FILE>` input on both the compatibility form and the subcommands: a JSON policy document is strictly deserialized through `PolicyDocument` and proven through `ValidatedPolicy` before any evaluation — unknown fields, unknown schemas, out-of-vocabulary values, and caps above the double-safe ceiling are refused with the exact typed reason and exit `2` before the archive is touched. A validated policy that does not authorize the selected format produces the ordinary evidence-bearing rejection, and the receipt binds the caller policy's own id and digest.

- The staged-tree audit now hashes files with a fixed 64 KiB buffer instead of loading each expanded file into memory.
- Layout roots now bind every member's complete local-header, payload, optional descriptor, and central-header ranges. Public content-root calculation returns unavailable for unverified members or malformed digests.
- Directory entries now require Store, zero sizes, and the CRC32 of empty content. LFH and CDH CRC fields must agree when no data descriptor is present.
- Malformed and unsupported inputs report a partial structure view instead of claiming a complete member inventory.
- Over-cap caller byte slices retain an honest `memory-borrowed` snapshot classification. A path that grows beyond the cap no longer reports a digest of only the bounded prefix as if it covered the complete archive.

## [0.1.0-alpha.2] - 2026-08-21

### Added

- DEFLATE verification now requires exactly one valid raw stream to consume every declared compressed byte. Trailing data and concatenated streams receive stable codec findings.
- Windows stages now receive a protected effective-TokenUser-only inheritable DACL during the existing atomic `NtCreateFile` operation and are verified through the returned handle before member writes.
- Materialization receipt v2 records the Windows storage policy, filesystem and device-scope observations, persistent-ACL and read-only flags, and stage-ACL verification without exposing a SID or volume identity.
- New `materialize.unsupported_filesystem` and `materialize.unsafe_stage` findings distinguish fail-closed Windows storage admission from stage-security verification.

### Changed

- Relicense the project from MIT to Apache-2.0.
- Windows materialization now supports only non-remote, writable NTFS parents that report persistent ACLs. ReFS, FAT-family filesystems, remote shares, read-only volumes, and ambiguous volume queries reject before staging.
- Current-contract documentation now distinguishes unsigned receipts from future attestations, documents source-digest unavailability, and aligns platform, cleanup, durability, and walkthrough claims with executable behavior.
- Native archives now include target-specific third-party license bundles generated and verified from the locked release dependency graphs.
